# C 盘不够用怎么无损扩容：三种做法的实测对比与四个踩坑清单

> 利益披露：作者所在团队维护文末提到的 ScsExpand，与该产品存在利益关系。文中所有分区表、容量数字都来自我自己在 Windows 10/11 上的实测，仅代表我的环境。

## 一、先说结论

"C 盘满了"这件事有三条路：清理、扩容、换盘。清理和换盘大家都熟，扩容最容易被误解——很多人以为扩容 = 格式化大分区再合并。实际上 Windows 自带的「磁盘管理」在绝大多数情况下**根本做不到**无损扩容：它只能删掉一个位于待扩容分区**右侧**的相邻卷，而且删掉之后那部分空间变成「未分配」，还得再新建卷，等于你亲手把数据全清空一次。

我的经验是：只有当「未分配空间紧贴在目标分区右边」时，Windows 自带工具才够用。分区表交错、GPT/动态磁盘混合、第三方分区工具留下的尾部分区这些情况，自带工具全部无解。

## 二、为什么「磁盘管理」扩容不了

Windows 的卷管理底层依赖分区表里连续的地址空间。要把 D 盘的空间给 C 盘，D 必须物理上紧挨在 C 的右边，而且中间不能隔着 E。

三个常见卡点：

1. **顺序反了** —— 磁盘布局是 C → D → E，你想要 E 的空间，磁盘管理就找不到入口，只能先把 D 删掉，而 D 里还有数据；
2. **动态磁盘/MBR 未转 GPT** —— 动态磁盘没有可靠的扩展路径，MBR 的 2TB 上限也需要先转 GPT；
3. **系统盘的 100MB/450MB 保留分区** —— OEM 机器常在 C 后面插一个恢复分区，直接把它挪走不现实。

## 三、方案一：清理（先别急着扩容）

说实话，多数「C 盘不够用」是几类东西堆积出来的：`C:\Users\<你>\AppData\Local\Temp`、Windows 更新残留 `C:\Windows\SoftwareDistribution\Download`、休眠文件 `hiberfil.sys`、以及 Docker/WSL 的虚拟磁盘。

我在自己机器上实测：关掉休眠 + 清空 Windows 更新缓存 + 清 Temp，腾出约 42GB，够撑半年。**在动分区之前，先花半小时统计一下真正占空间的是什么**——很多人扩容完三个月又满，因为问题根本不是容量，是垃圾文件没被管住。

## 四、方案二：备份后重装（最干净但最耗时）

`diskpart` 删卷 → 恢复分区 → 用第三方工具把剩余空间分配给 C → 恢复备份。这条路最"标准"，代价是所有软件要重装、系统要重新激活、驱动要重打。我在两台工作机上做过，整机恢复加分区调整，耗时 4~6 小时，中间任何一步出问题都有丢数据的风险。**只有当分区表结构很干净（单系统盘 + 一个数据盘）时，这条路才值得。**

## 五、方案三：原地移动分区（无损，但需要外部介质）

思路是：准备一块容量 ≥ 目标分区大小的**外部磁盘**（移动硬盘/U 盘都行），把中间那些要"让位"的分区先整体搬到外部盘，然后在原地腾出连续的未分配空间，再把它加给目标分区。

以「C → D → E，想把 E 的 200GB 给 C」为例：

1. 把 E 完整备份到外部盘，并校验；
2. 删掉 E，腾出 200GB 未分配空间；
3. 把 D 也备份到外部盘，删掉 D，此时 C 右边出现连续 400GB 未分配空间；
4. 扩展 C，吃掉这 400GB；
5. 重新建 D 和 E，把数据拷回去。

关键点是 **所有中间分区的数据都必须完整落到外部盘**，一次搬不完就分批，中途失败也要能原地重来。所以外部盘的容量要留足冗余——我一般按「被移动分区的总容量 × 1.5」准备。

## 六、四个真实踩过的坑

1. **UEFI 分区表不是 GPT** —— 某些品牌机出厂是 UEFI + MBR，换主板或换硬盘时克隆工具会把分区表搞成 MBR，重启直接进不了系统。克隆前务必用 `diskpart` 的 `list disk` 看清分区表类型。
2. **BitLocker 没解密就动分区** —— Windows 11 默认开设备加密，BitLocker 状态下调整分区会被系统直接拒绝。处理顺序是：先备份恢复密钥 → 暂停保护 → 做分区操作 → 重新恢复保护。
3. **休眠文件搬不动** —— `hiberfil.sys` 和 `pagefile.sys` 是被系统锁定的，分区被移动后它们不会跟着走，需要重启后让系统在新位置重建。
4. **恢复分区被顺手当成可删空间** —— OEM 的恢复分区是售后找回数据用的，有些机器还有 OEM 自定义引导。我有一次没留意，把 OEM 保留分区一起搬走，结果本地重装找不到引导记录。移动前一定要在 `diskpart` 里逐个核对分区类型（`System` / `Recovery` / `OEM`）。

## 七、什么时候值得做

如果你只是缺 50GB，先做第三节的清理；如果你要腾出 200GB 以上，而且分区顺序不允许你直接扩展，那就走第五节的原地移动方案，注意准备充足外部介质和 BitLocker 密钥；如果你不在乎重装一遍、机器是干净的单分区布局，直接备份重装反而最省心。
